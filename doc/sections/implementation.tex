\section{Implementation}
\label{sec:implementation}

This section describes how the knowledge base, the inference engine and the
explanation module are realized: the tools, the modules of the system, the
form of the rules, the question protocols, the six uncertainty methods and the
proof trees.

\subsection{Tools}

PESAD is written in SWI-Prolog~\cite{swipl}. Apart from the standard library,
it uses the libraries for JSON, needed by the evaluation from test results, and
the Machine Query Interface (MQI)~\cite{swipl-mqi}, through which the Python
layer of chapter~\ref{chap:interfaces} drives the engine. Both the
Telegram bot and the web API are written in Python, with the packages
\code{python-telegram-bot}, FastAPI and \code{swiplserver}. They are deployed as
Docker images built by the continuous integration of the repository, which also
runs the validation suite at each push.

\subsection{System Architecture}

The system is organized by responsibility, following the conceptual
architecture of an expert system (knowledge base, inference engine, user
interface), with one file per concern (table~\ref{tab:modules}). From the terminal the system is started by \code{start.pl}, the bot and the
web API by \code{bot\_boot.pl}, and both load the same knowledge base and the
same engine.

\subsection{Knowledge Base}
\label{sec:kb}

The rules of levels I to III have a common form. The premises are proved in
order, each with the truth value it is required with; then the list of their
certainties is passed to \code{certainty/6}, together with the identifier of the
conclusion, the inference level, the certainty of the rule and the truth value
of the conclusion. As an example, the criterion set of panic disorder (level~II)
requires recurrent unexpected attacks (A), at least one month of concern or of
maladaptive change of behavior (B), and that the disturbance be \emph{not}
better explained by another mental disorder (D):

\begin{lstlisting}
disorder_nc(panic_disorder,Patient,CF,TV) :-
    symptomatic_manifestation(recurrent_unexpected_panic_attacks,Patient,CF1,true),
    symptomatic_manifestation(panic_consequences_concern,Patient,CF2,true),
    symptomatic_feature(duration_at_least_one_month,Patient,CF3,true),
    unless_absent([CF1,CF2,CF3],
        symptomatic_feature(panic_better_explained_by_other_disorder,
                            Patient,CF4,false),[CF4]),
    certainty(panic_disorder,2,[CF1,CF2,CF3,CF4],0.97,CF,TV).
\end{lstlisting}

The goal of level~I adds criterion C, i.e., that the disturbance be not
attributable to a substance or to another medical condition. This criterion is
shared by many disorders, and it is written once, as the two parent disorders
\code{associated\_substance\_induced\_alteration} and
\code{associated\_general\_medical\_condition}, both required false:

\begin{lstlisting}
disorder(panic_disorder,Patient,CF) :-
    primary(panic_disorder,Patient,CF1,CF2,CF3),
    certainty(panic_disorder,1,[CF1,CF2,CF3],0.97,CF,true).
\end{lstlisting}

The wrapper \code{unless\_absent/3} calls its goal only when none of the
certainties already computed for the rule is $0$, and otherwise sets the
remaining certainties to $0$. Hence, the exclusion and specifier questions of a
disorder whose core criteria have already failed are not posed, which shortens a
consultation considerably. Each rule has a certainty, a constant between $0.95$
and $0.98$ at levels I and II, chosen by hand (and somewhat arbitrarily) to
reflect the specificity of the criteria. It is $1$ for the criteria answered by
a single question, whose uncertainty is that of the answer.

A specifier that identifies a goal may be a premise of the goal (e.g., ``with
dissociative symptoms'', or the presentations of ADHD, which require A1 and A2
with the appropriate truth values). Otherwise, it is a \emph{selective}
question, whose answer admits one goal of the family:

\begin{lstlisting}
disorder(attention_deficit_hyperactivity_disorder_mild,Patient,CF) :-
    disorder_nc(attention_deficit_hyperactivity_disorder,Patient,CF1,true),
    selected(CF1,adhd_severity(severity_mild)),
    certainty(attention_deficit_hyperactivity_disorder_mild,1,[CF1],0.97,CF,true).
\end{lstlisting}

where \code{selected/2}, like \code{unless\_absent/3}, poses the question only
if the disorder is not already ruled out. Age-dependent parts of the
criteria are branches on the age band: e.g., separation anxiety disorder
requires 4 weeks below 18 years and about 6 months in adults, generalized
anxiety disorder requires 1 associated symptom in children and 3 in adults, and
the preschool subtype of posttraumatic stress disorder has its own clusters.
When the exact age is known (as in the evaluation from test results), it is
used for the thresholds that the manual places at a given age, such as the 5
symptoms of ADHD from age 17.

\subsection{Inference Engine}

The inference engine comprises the acquisition of the facts from the user, the
management of uncertainty and the bookkeeping of the proof trees; Prolog provides the backward chaining and the backtracking.

\subsubsection{Knowledge Acquisition}
\label{sec:acquisition}

The elementary facts are obtained through three question protocols,
implemented in \code{ask.pl}. An answer is stored in the working memory as a
fact \code{known(Answer, Attribute, Value, CF)}, and a question already answered
is not posed again.

The \emph{criterion ask} verifies a criterion of $N$ yes/no items of which at
least $M$ are required ($1 \le M \le N$). Each item is answered \emph{yes} or
\emph{no} with a certainty $c$, and a \emph{no} contributes $1-c$. Its certainty
is the smallest among the $M$ largest certainties of the items,
i.e., denoting by $c_{(1)} \ge c_{(2)} \ge \dots \ge c_{(N)}$ the certainties
sorted in decreasing order,
\begin{equation}\label{eq:criterion}
\cf_{\text{criterion}} \;=\; c_{(M)} \,.
\end{equation}
For instance, with $N=3$ items of certainties $0.4$, $0.7$ and $0.6$ and $M=2$,
the criterion has certainty $0.6$. Note that (\ref{eq:criterion}) is the minimum over the best $M$ items under all
the uncertainty methods, since choosing \emph{which} $M$ items satisfy the
criterion is a matter of selection.

The \emph{multiple ask} poses a question with a list of options, of which a
subset is admitted by the rule (e.g., the durations of at least 6 months). If
the chosen answer $a$, given with certainty $c$, is admitted, the premise has
certainty $c$. Otherwise, the residual certainty $1-c$ is distributed evenly over
the other options:
\begin{equation}\label{eq:multiple}
\cf \;=\;
\begin{cases}
c & \text{if $a$ is admitted,}\\[4pt]
\dfrac{1-c}{\,|\text{options}|-1\,} & \text{otherwise.}
\end{cases}
\end{equation}
The \emph{selective ask} is used for the age band and for the selective
specifiers: the admitted option succeeds with certainty $1$, and any other
option makes the goal fail (and therefore gives it certainty $0$). To a pending
question the user may also answer \emph{why}, which prints the diagnostic reason
of the question before posing it again.

\subsubsection{Uncertainty Management}
\label{sec:uncertainty}

Certainties lie in $[0,1]$ and are managed in \code{uncertainty.pl}. The
certainty of the antecedent of a rule with premises of certainties
$c_1, \dots, c_n$ is obtained by folding a t-norm $T$ over them,
\begin{equation}\label{eq:antecedent}
\cf_{\text{ant}} \;=\; T\big( \dots T( T(1, c_1), c_2 ) \dots, c_n \big) ,
\end{equation}
which does not depend on the order of the premises since a t-norm is
commutative and associative, and has $1$ as neutral element~\cite{klement}. As in MYCIN~\cite{shortliffe-buchanan}, the certainty of the conclusion combines
that of the antecedent with the certainty $\cf_{\text{rule}}$ of the rule, and
its complement is taken when the conclusion is required false:
\begin{equation}\label{eq:consequent}
\cf_{\text{cons}} \;=\;
\begin{cases}
\cf_{\text{rule}} \cdot \cf_{\text{ant}} & \text{if the conclusion is required true,}\\[4pt]
1 - \cf_{\text{rule}} \cdot \cf_{\text{ant}} & \text{if it is required false.}
\end{cases}
\end{equation}
If the clinician answers \emph{yes} with certainty $0.2$ to ``the panic attacks
are better explained by another mental disorder'', the exclusion contributes
$1 - 1 \cdot 0.2 = 0.8$ to the rule of panic disorder; an answer \emph{no} with
certainty $1$ contributes $1$.

Uncertainty methods differ in the t-norm of (\ref{eq:antecedent}). Five
t-norms are used~\cite{klement,hajek}, i.e., for $a, b \in [0,1]$, the minimum
(or G\"odel) t-norm, the product, the \L{}ukasiewicz t-norm, the Hamacher
product and the Einstein product:
\begin{align}
T_{M}(a,b) &= \min(a,b), \label{eq:tmin}\\
T_{P}(a,b) &= a\,b, \label{eq:tprod}\\
T_{L}(a,b) &= \max(0,\, a+b-1), \label{eq:tluk}\\
T_{H_0}(a,b) &=
\begin{cases}
0 & \text{if } a=b=0,\\[2pt]
\dfrac{a\,b}{a+b-a\,b} & \text{otherwise,}
\end{cases} \label{eq:tham}\\
T_{E}(a,b) &= \frac{a\,b}{2-(a+b-a\,b)} . \label{eq:tein}
\end{align}
The last two are the members of the Hamacher family
$T^{H}_{\lambda}(a,b) = a\,b / (\lambda + (1-\lambda)(a+b-a\,b))$ for $\lambda=0$
and $\lambda=2$~\cite{hamacher}, and the family gives the product for
$\lambda=1$. They are ordered pointwise as
\begin{equation}\label{eq:order}
T_{L} \;\le\; T_{E} \;\le\; T_{P} \;\le\; T_{H_0} \;\le\; T_{M} ,
\end{equation}
the minimum being the largest t-norm and the only idempotent one~\cite{klement}.
Hence, on the same answers, the minimum gives the largest certainties and the
\L{}ukasiewicz t-norm the smallest. In detail, the six methods are as follows.
\begin{itemize}
  \item \code{cf} (the default), with the minimum (\ref{eq:tmin}), which gives
  the certainty factors of MYCIN: a criterion is as certain as its weakest
  premise;
  \item \code{fuzzy}, with the product (\ref{eq:tprod});
  \item \code{fuzzy\_membership}, with the minimum, in which the duration and
  the number of panic attacks are entered as numbers and converted by
  membership functions (see below);
  \item \code{lukasiewicz}, \code{hamacher} and \code{einstein}, with
  (\ref{eq:tluk}), (\ref{eq:tham}) and (\ref{eq:tein}).
\end{itemize}
The rule chaining (\ref{eq:consequent}) and the complement are shared by all
the methods. Differences among the t-norms grow with the number of premises
of a rule, which is large for the polythetic disorders. Table~\ref{tab:tnorms}
gives the certainty of the antecedent of a rule with $n$ premises of certainty
$0.8$ each: with the minimum it does not depend on $n$, and with the product it
decreases geometrically. With the \L{}ukasiewicz t-norm it is $0$ from $n=5$
on, i.e., five premises that are each ``fairly sure'' do not support the
conclusion at all (cf. the case \code{uncertain\_ptsd} in
section~\ref{sec:val-results}).

In the method \code{fuzzy\_membership}, the durations and the number of panic
attacks are entered as numbers (months and attacks). The certainty of a premise
is then the membership grade of the number to the fuzzy set that replaces the
discrete options admitted by the rule~\cite{zadeh}. These sets are piecewise
linear: ``at least 6 months'' has membership $\mu(m) = \min(1, \max(0,
(m-3)/3))$, i.e., $0$ up to 3 months and $1$ from 6 months on, and ``less than 6
months'' is its complement; ``at least 1 month'' rises from $0$ at one week to
$1$ at one month, ``from 3 days to 1 month'' is a trapezoid, and ``two or more
attacks'' rises from $0$ at one attack to $1$ at two. With the first set
(table~\ref{tab:duration-membership}) a five-month duration satisfies the ``at
least 6 months'' criterion with certainty $0.67$, instead of failing it. This is
(arguably) what the manual means when it qualifies several of its six-month
durations with ``typically''.

While the certainty of a conclusion is computed, the rule is recorded (as
\code{rule\_I/4}, \code{rule\_II/5} or \code{rule\_III/6}, according to its
level) with a hierarchical index, and the facts are recorded under the index of
the rule that used them. These records form the proof trees traversed by the
explanation module.

\subsubsection{Explanation Module}

The \emph{why} is implemented in \code{ask.pl}: the answer \emph{why} prints the
text \code{explanation/3} associated with the item, which states the criterion
of the manual that the item serves. The \emph{how} is implemented in
\code{explanation.pl}. After a diagnosis the user may request the proof tree of
a goal, and \code{print\_tree/1} prints, indented by level, the conclusions with
their certainty and truth value, the rules (marked as \emph{deduced}) being
distinguished from the facts (marked as \emph{stated}). The web API returns the
same tree as text and as nested JSON nodes; in the evaluation from test results
each node also carries its status and its certainty bounds (cf.
section~\ref{sec:evaluate}).

\subsection{User Interface}

The terminal shell (\code{shell.pl}) is a read--evaluate--print loop, described
in chapter~\ref{chap:usage}. At start-up the user chooses the language
(English or Italian) and the uncertainty method. The language, stored in the
dynamic fact \code{language/1}, drives the messages through
\begin{lstlisting}
decode(Key,Text) :- language(Language), label(Language,Key,Text), !.
decode(Key,Key).
\end{lstlisting}
so that the knowledge base and the engine work on language-neutral keys. Each
locale file maps a key to a text (\code{label/3}) and, for the items, to an
explanation (\code{explanation/3}). Commands, being control tokens, are typed in English. Adding a language amounts to adding a locale file, and
the validation suite checks that goals, items, questions and options have a
text in both languages. Input and output go through \code{ui\_read/2} and
\code{ui\_topic/1} (\code{bot\_io.pl}), which read from the terminal or, in
session mode, return to the Python layer the question with a structured
description of it (its type, its options and its explanation). Hence, the same
code serves the terminal, the bot and the web API.
